# Abdul Rahman — Developer Portfolio

A personal portfolio for exploring Abdul Rahman's full-stack projects, development experience, education, and technical writing. Built for visitors, collaborators, and potential employers who want to understand his work and get in touch.

[Website](https://abdulrdeveloper.me) · [Technical blog](https://blog.abdulrdeveloper.me) · [GitHub](https://github.com/abdulrdeveloper)

## What visitors can explore

- **Selected work:** Klar, Sonik, Glimpse, and DevScope, each with a project page, feature summary, technology stack, and links to the demo and source repository.
- **Developer profile:** introduction, categorized skills, education, and the current Full Stack Developer internship at Spurvance Labs.
- **GitHub activity:** live follower count and a contribution calendar for the current year, with loading and unavailable states.
- **Technical writing:** the three latest article previews on the homepage and the full preview list on `/blog`. Articles open on the external blog.
- **Contact and CV:** social and contact links, plus a locally hosted PDF CV that opens in a new tab.
- **Display preferences:** light and dark themes, responsive layouts, keyboard focus indicators, a skip-to-content link, and a hero animation that respects reduced-motion preferences.

## Technology and architecture

| Area | Implementation |
| --- | --- |
| Framework | Next.js 16.1.6 with the App Router and React 19.2.3 |
| Language and styles | TypeScript and Tailwind CSS 4 |
| Themes | `next-themes`, defaulting to the visitor's system preference |
| Content | Typed local files in `constants/` |
| Delivery | Static HTML and assets exported to `out/` |
| Browser data | GitHub profile API and a contribution-calendar provider |

The portfolio requires no database, application backend, API keys, or environment file. Projects showcased here are separate applications; their databases, authentication, and AI integrations are not dependencies of this portfolio.

Page content is generated at build time. Theme switching and GitHub activity use client-side JavaScript. Fonts are configured through `next/font/google` in [app/layout.tsx](app/layout.tsx).

## Run locally

Requirements: **Node.js 20.9 or newer**, npm, and network access to install dependencies and download Google fonts during the build.

```bash
git clone https://github.com/abdulrdeveloper/abdul-portfolio-tamplate.git
cd abdul-portfolio-tamplate
npm ci
npm run dev
```

Open [localhost:3000](http://localhost:3000). The npm instructions use the committed `package-lock.json`; a `pnpm-lock.yaml` also exists, but switching package managers is not required.

| Command | Purpose |
| --- | --- |
| `npm run dev` | Start the local Next.js development server |
| `npm run lint` | Run ESLint with Next.js and TypeScript rules |
| `npm run build` | Build the site, check TypeScript, and export production files to `out/` |

Article previews are maintained manually in `constants/blog.ts` and sorted newest first by publication date. Publishing on the external blog does not automatically update this repository. Add the preview entry and rebuild to include a new article.

When replacing the CV, keep its filename or update the CV link in `constants/site.ts`. The sharing PNG is committed separately from its SVG source; editing the SVG does not automatically regenerate the PNG.

## GitHub activity

[lib/github.ts](lib/github.ts) makes two public requests in the visitor's browser:

| Data | Endpoint |
| --- | --- |
| Follower count | `https://api.github.com/users/{username}` |
| Contribution calendar | `https://github-contributions-api.jogruber.de/v4/{username}?y={year}` |

The username is derived from `siteConfig.socialProfiles.github`. The year follows the visitor's browser date. No GitHub token is used.

Activity loads when the section mounts, refreshes every 24 hours while the page remains open, and refreshes when an overdue tab becomes visible. Requests time out after 15 seconds, and returned counts and calendar entries are validated before display. Upstream rate limits, caching, or provider outages can affect availability and freshness.

If one request fails, the other can still display its data. A failed refresh keeps previously loaded data visible and reports the problem. Before data loads, counts show a dash; the profile link remains available without JavaScript. The contribution graph supports horizontal scrolling on small screens.

## SEO and sharing

- [app/layout.tsx](app/layout.tsx) defines the default title, description, canonical URL, author, favicon, Open Graph image, and Twitter card metadata.
- The project collection, project detail pages, and blog collection define their own titles, descriptions, canonicals, and Open Graph text.
- [components/seo/JsonLd.tsx](components/seo/JsonLd.tsx) provides Person, WebSite, ProfilePage, collection, project, and breadcrumb structured data.
- [app/robots.ts](app/robots.ts) and [app/sitemap.ts](app/sitemap.ts) generate the crawl files during the static build.

When changing the domain or identity, review the page metadata and structured-data helpers as well as `constants/site.ts`; some names and profile details are written directly in those files. Review the sharing artwork too. Search Console verification is not currently configured in the root metadata.

## Deploy

```bash
npm ci
npm run lint
npm run build
```

Publish the contents of **`out/`** to a static host. [next.config.ts](next.config.ts) sets `output: "export"` and disables the server image optimizer. No running Next.js server or `npm start` command is needed.

Configure the host to resolve clean URLs such as `/projects/klar` to their exported HTML files and serve `404.html` with a 404 status for unknown paths. Keep the generated `/_next/` assets and public files alongside the HTML. The site uses root-relative URLs and is configured for a domain root, rather than a repository subdirectory.

The repository does not include a hosting deployment workflow. Configure the build command, output directory, domain, HTTPS, redirects, and caching in the chosen host. Rebuild and redeploy after editing local content, metadata, images, or the CV.

After deployment, check direct navigation to a project page, the CV, sharing image, sitemap, robots file, and an unknown URL. Confirm that the deployed domain matches `siteConfig.url`.

## Browser data and external services

The application has no contact form, login system, or analytics script. The theme preference is stored in the browser's local storage by `next-themes`. Clearing that storage removes the saved preference.

Loading GitHub activity sends requests directly from the visitor's browser to GitHub and the contribution-calendar provider. Those services receive request information such as the visitor's IP address and requested profile. Following demo, article, social, email, or messaging links opens a separate service. Hosting access logs and third-party data handling depend on the services used; this repository does not define their retention policies.
